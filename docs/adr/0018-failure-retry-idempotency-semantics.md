# Failure, retry, and idempotency semantics for every agent and checkpoint

An independent architecture review (`.scratch/architecture-review-2026-09-15.md`, Critical Finding #4) found zero defined behavior anywhere in the spec for: an LLM Inference Service outage mid-call, a failed LangGraph checkpoint write, malformed structured output from an agent, or two Lead/Approvers resolving the same `interrupt()` concurrently. Over a 30+ day intake window plus indefinite AG/pre-exit revision cycles (ADR-0010), these are not edge cases — they are near-certain to occur in production, and silent double-processing of a checkpoint resolution directly undermines the audit trail's (ADR-0007) claim to be the regulatory source of truth for what was approved and by whom.

We're defining four policies, applied uniformly across every agent and every `interrupt()`:

1. **Tool-call retry policy.** Every tool call (`notice_corpus.*`, `edm.query`, `supersession_graph.check`) gets a bounded retry with backoff on transient failures (timeout, connection error). Critically: **a tool-unavailable result is a distinct outcome from "no matching data found,"** and must never collapse into the same code path — for `notice_corpus.get_clause()` under the citation-grounding rule (ADR-0004), treating a timeout as "no clause exists" would silently produce a wrong `insufficient_grounding` verdict instead of a correct one that was merely delayed. See `lfi-workflow-phase1-preexam-v1.html`'s guardrail card for the concrete instance.
2. **Idempotency on state-mutating calls.** Every state-mutating agent invocation, and `log_checkpoint()` specifically, carries an idempotency key so a replayed or re-run LangGraph node does not double-write state or double-log an audit entry.
3. **Optimistic concurrency on `interrupt()` resolution.** Every checkpoint carries a version/etag. A second concurrent resolution attempt on an already-resolved checkpoint is rejected with an explicit conflict, not silently overwritten or double-applied.
4. **Structured-output validation and repair.** Every agent's output is validated against its schema before being accepted. One automatic repair retry is allowed (re-prompt with the validation error); a second failure escalates to human review rather than accepting malformed output or guessing a fix.

This is worth its own ADR because these policies are cross-cutting — they apply identically to every agent in `agent-specifications.md`, not to one — and because durability claims already made elsewhere (ADR-0001's "interrupt/resume is durable across the 30-day RFI window") are only true if the underlying checkpoint write is actually transactional and idempotent, which nothing previously stated explicitly.
