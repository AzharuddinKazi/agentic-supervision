# Testing strategy beyond the golden eval set: unit, integration, and a canary/rollback process for model swaps

An independent architecture review (`.scratch/architecture-review-2026-09-15.md`, High Finding #10) found that ADR-0016's offline golden eval set only gates citation-validity and a human-graded sample before a prompt/model change ships — it catches nothing else: no unit tests for tool error paths, no integration test for the LangGraph graph's structural correctness (does resume-from-checkpoint actually restore state after a crash? does the AG revision loop actually route back to Findings & Reporting rather than silently dropping state?), no load test, no chaos/failure-injection test, and — most concretely, given decision 49 explicitly keeps the model swappable — no canary or rollback process for a model swap while examinations are mid-flight for 30+ days with two multi-week revision loops layered on top.

**Decision, four additions to the testing story, all required before implementation is considered done, not just before go-live:**

1. **Unit tests for every tool's error/timeout path.** Every tool contract in `docs/architecture/tool-contracts.md` gets a corresponding unit test that exercises its timeout and error-response shape specifically — not just the happy path — including the "unavailable ≠ no result" distinction ADR-0018 already requires in code.
2. **LangGraph integration test suite.** Exercises every `interrupt()`/resume path and both revision loops (AG review loop, pre-exit loop — ADR-0010) against a simulated crash-and-resume, verifying state is restored correctly and no `audit_log[]` entry is duplicated (ADR-0018's idempotency guarantee, tested, not just specified).
3. **Canary process for model/prompt swaps.** Before a full cutover: run the candidate model/prompt against (a) the golden eval set (ADR-0016) and (b) a shadow-traffic sample of real (anonymized) in-flight examination data, then compare human-agreement rate on a pilot subset of live examinations before promoting the candidate to the default model for all new work. This is required specifically because decision 49 keeps the model swappable as a real, expected operational event, not a hypothetical.
4. **Explicit in-flight-examination policy for a model swap.** When a swap ships: examinations already mid-cycle are **pinned to the model version they started under until they reach a natural phase boundary** (end of Phase 1, end of Phase 2, or full completion) — not switched mid-clause-verdict-loop to a different model with potentially different behavior. New examinations use the new default. We chose pinning over always-latest specifically because an examination spanning weeks with human sign-offs already given against one model's outputs should not have its remaining agent calls silently produced by a different model without that being a visible, logged event — if a mid-cycle switch is ever needed (e.g., the pinned model is deprecated), that is a deliberate, logged exception, not the default behavior.

**Why this matters:** the golden-eval-set gate alone catches citation quality regressions but nothing about the graph's structural correctness or concurrent-model-version behavior during a swap — for a system with 30+ day in-flight examinations and revision loops that can run for weeks (ADR-0010), an unpinned or untested model swap mid-cycle is a realistic production incident, not an edge case, given decision 49 already commits to swappability actually being used.

**Explicitly deferred, per the review's own priority ordering:** full TDD-style sequence diagrams for every internal REST call, and the on-call/runbook document. These matter before go-live, not before implementation starts — team ownership is already sketched via the deployment diagram's `tag` fields, and the runbook can be written once the system exists to operate.
