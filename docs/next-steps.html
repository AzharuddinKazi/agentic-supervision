1. Executive Summary & Current State

The Agentic Supervision system augments FPSD examiners across all three phases of an LFI compliance examination without replacing human regulatory authority. All foundational design work is complete:

  • 22 Design Rounds & 138 Numbered Decisions: Captured in detail in docs/decision-log.md.
  • 32 Architecture Decision Records (ADRs): Fully converted to the standard Michael Nygard format in docs/adr/.

  • Production Readiness Baseline: Living PRD and TDD documents (v1.2.0), comprehensive agent-specifications.md, and explicit tool-contracts.md.
  • Current Code Status: 100% design and specification artifacts. No application code has been written yet.

3. Phased Implementation Roadmap (Build Order)

Following docs/TDD.md §8.1, engineering proceeds strictly by architectural dependency:

Sprints 1–2: Foundation Data Stores & Ingestion Layer
Data layer and ingestion primitives that all downstream agents depend upon.
  • Oracle Fraud DB Schema: Tables for Notice Corpus, RFI Store, Audit Trail, and Analysis Output (ADR-0012, ADR-0014). Encrypted BLOB document storage (ADR-0019, ADR-0032).
  • Pluggable Ingestion Adapter: Build SFTP adapter with list_documents, get_metadata, and fetch_document contracts (ADR-0006).
  • Notice Corpus Service: PDF ingestion, OCR segmentation, and hybrid lookup (search + exact-match get_clause + single-hop supersession_graph.check, ADR-0027).
  • Tamper-Evident Audit Trail: Append-only hash-chained logging service (log_checkpoint contract, ADR-0007).
Sprint 3: Deterministic Intake Tracker (Rule-Based Service)
Lowest-risk agent component — purely rule-based, no LLM dependency.
  • RFI Parser: Ingest pre-sent Excel/Word RFIs into structured questions bank (decision 85).
  • Folder Polling Engine: Track submissions against fixed bank directory conventions.
  • Event Disambiguation: Emit all_submitted for Round-1 RFI completion; emit round_submitted(round: N) for further-submission rounds (decision 127).
Sprints 4–5: Model Client & Compliance Analyst Agent
The highest-stakes reasoning component, enforcing the central citation guardrail.
  • In-Tenant Model Client: Model-agnostic client calling self-hosted LLM via mTLS with structured output repair (ADR-0013, ADR-0019).
  • Citation Grounding Hard Rule: Non-negotiable exact-match check (ADR-0004). Force insufficient_grounding, needs human review on low confidence or tool errors (ADR-0018).
  • Gap Analysis & Question Drafting: LangGraph node batch-producing compliance verdicts and initial supervision question drafts.
Sprints 6–7: Meeting Facilitator & Findings Author
Phase 2 meeting support and Phase 3 post-exam findings generation.
  • Meeting Facilitator: Pre-meeting supervision questions sign-off gate (HITL Checkpoint 2). Post-meeting minutes text parsing to extract further_submission_requests[] (HITL Checkpoint 3). Human sufficiency check gate (HITL Checkpoint 4).
  • Deterministic Platform Tools: Deterministic EDM ratio calculation via quant_analysis.compute (ADR-0021) and versioned rubric evaluation via severity_rubric.lookup (ADR-0020).
  • Findings Author: Dual-track drafting (qualitative clause compliance + quantitative EDM context, never reconciled, ADR-0009/0011). Findings sign-off gate (HITL Checkpoint 5). Template fill for Word transmittal letter and PPT deck.
Sprints 8–9: Approval Coordinator, Dashboard UI & Observability
Final approval workflows, unified frontend, and telemetry integration.
  • Approval Coordinator: Pre-AG sign-off gate (HITL Checkpoint 6, ADR-0003). Side-by-side display of raw AG feedback vs. editable AI summary (HITL Checkpoint 8). Routine redraft loops back to findings drafting (ADR-0010).
  • Examiner Dashboard UI: Portfolio Home + 7 Tabbed Workspace (Setup, Intake, Gap Analysis, Meeting, Findings, Approval, Audit Log) with RBAC gating and optimistic concurrency etag checking (ADR-0008, ADR-0018, ADR-0029).
  • Observability & Metrics: OpenTelemetry tracing + Langfuse integration. Automated tracking of human-agreement rates at each checkpoint (ADR-0016).

4. Rollout Strategy & Go/No-Go Gates

Per docs/TDD.md §8.2, the system will not be cut over cold. It follows a 3-tier validation sequence:

  1. Shadow Mode (1–2 Examinations): System runs in parallel on real ongoing examinations. Outputs are evaluated offline by senior examiners against human work. No agent outputs surfaced live.
  2. Live Pilot (2–3 Examinations): System operates live with Lead/Approvers signing off at every checkpoint, with full manual fallback ready at any time.
  3. Strict Go/No-Go Production Gate:
    • 0 Citation Violations (Hard Gate): Zero instances of an ungrounded or fabricated clause reaching a signed-off finding (ADR-0004).
    • Healthy Human-Agreement Rate: Lead/Approver sign-off agreement stays within target band (e.g. 70%–92%), avoiding rubber-stamping / automation bias (ADR-0016).
    • 0 Unexplained Audit Violations: Zero hash-chain integrity alarm failures.
